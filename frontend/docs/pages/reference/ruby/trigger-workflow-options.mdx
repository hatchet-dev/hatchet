# Class Hatchet::TriggerWorkflowOptions

**Inherits:** `Object`

Options for triggering a workflow run

**Example: Trigger with metadata and priority**

```ruby
Hatchet::TriggerWorkflowOptions.new(
  additional_metadata: { "user_id" => "123" },
  priority: 3
)
```

## Attributes

## `additional_metadata`

_Read-only attribute_

- **Returns** [Hash, nil] Additional metadata to attach to the run

## `child_index`

_Read-only attribute_

- **Returns** [Integer, nil] Child index for deterministic replay

## `desired_worker_labels`

_Read-only attribute_

- **Returns** [Hash, nil] Desired worker labels for scheduling

## `key`

_Read-only attribute_

- **Returns** [String, nil] Deduplication key

## `parent_id`

_Read-only attribute_

- **Returns** [String, nil] Parent workflow run ID (auto-set from context vars)

## `parent_step_run_id`

_Read-only attribute_

- **Returns** [String, nil] Parent step run ID (auto-set from context vars)

## `priority`

_Read-only attribute_

- **Returns** [Integer, nil] Priority level (1-4, higher = more priority)

## `sticky`

_Read-only attribute_

- **Returns** [Boolean, nil] Whether to use sticky scheduling
