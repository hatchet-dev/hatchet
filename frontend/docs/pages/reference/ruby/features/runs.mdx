# Class Hatchet::Features::Runs

**Inherits:** `Object`

Runs client for interacting with Hatchet workflow run management API

This class provides a high-level interface for creating and managing workflow
runs in the Hatchet system. It wraps the generated REST API client with a more
convenient Ruby interface.

- **Since** 0.1.0

**Example: Creating a workflow run**

```ruby
runs = Features::Runs.new(rest_client, config)
response = runs.create(
  name: "my-workflow",
  input: { key: "value" },
  additional_metadata: { source: "api" }
)
```

## `create`

`create(name:, input:, additional_metadata: = nil, priority: = nil)`

Creates a new workflow run in the Hatchet system

This method triggers a new workflow or task run for the specified workflow
using the provided input data. The workflow run will be queued according to
the workflow definition on an available worker.

IMPORTANT: It's preferable to use \<code>Workflow.run\</code> (and similar) to
trigger workflows if possible. This method is intended to be an escape hatch.

**Parameters:**

| Name                  | Type           | Description                                          |
| --------------------- | -------------- | ---------------------------------------------------- |
| `name`                | `String`       | The name of the workflow to trigger                  |
| `input`               | `Hash`         | The input data for the workflow run                  |
| `additional_metadata` | `Hash, nil`    | Additional metadata associated with the workflow run |
| `priority`            | `Integer, nil` | The priority of the workflow run                     |

- **Raises** [ArgumentError] If the workflow_name or input parameters are nil or invalid
- **Raises** [Hatchet::Error] If the API request fails or returns an error
- **Returns** [HatchetSdkRest::V1WorkflowRunDetails] The details of the triggered workflow run
- **Since** 0.1.0

**Example: Creating a workflow run**

```ruby
response = runs.create(
  name: "simple-workflow",
  input: { user_id: 123, action: "process_data" },
  additional_metadata: { source: "api", priority: "high" }
)
```

## `poll`

`poll(workflow_run_id, interval: = 1.0, timeout: = nil)`

Poll for workflow run completion with configurable interval and timeout

This method repeatedly calls `get` until the workflow run reaches a terminal
state (succeeded, failed, or cancelled) or the timeout is reached.

**Parameters:**

| Name              | Type           | Description                                               |
| ----------------- | -------------- | --------------------------------------------------------- |
| `workflow_run_id` | `String`       | The ID of the workflow run to poll                        |
| `interval`        | `Numeric`      | The polling interval in seconds (default: 1.0)            |
| `timeout`         | `Numeric, nil` | The maximum time to poll in seconds (default: no timeout) |

- **Raises** [Timeout::Error] If the timeout is reached before completion
- **Raises** [Hatchet::Error] If the API request fails or returns an error
- **Returns** [HatchetSdkRest::V1WorkflowRunDetails] The final workflow run details
- **Since** 0.1.0

**Example: Poll with default settings (1s interval, no timeout)**

```ruby
result = runs.poll("workflow-run-123")
```

**Example: Poll with custom interval and timeout**

```ruby
result = runs.poll("workflow-run-123", interval: 2.0, timeout: 30.0)
```
