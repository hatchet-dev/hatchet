# Using PgBouncer

<Callout type="info">Only available in Hatchet v0.83.5 and above.</Callout>

If you're self-hosting Hatchet, you can put PgBouncer (version 1.21 or newer) in front of your database to share and reuse connections more efficiently.

To set this up, point the `DATABASE_PGBOUNCER_URL` environment variable at your PgBouncer instance, while keeping the `DATABASE_URL` still pointed to your PostgreSQL server address. Make sure PgBouncer is running with `pool_mode` set to `transaction`. See the [PgBouncer docs](https://www.pgbouncer.org/config.html) for all available settings.

## Statement timeouts

Hatchet runs its queries with a 30 second `statement_timeout` and `idle_in_transaction_session_timeout`. It sets them when a connection opens. In transaction pooling mode, that only reaches one server connection, so most queries run without them. Hatchet logs a warning on startup when server connections start without one of these timeouts.

On PgBouncer 1.26.0 or newer, have PgBouncer track both settings:

```ini
track_extra_parameters = statement_timeout, idle_in_transaction_session_timeout
```

Then add them to `DATABASE_PGBOUNCER_URL` as query parameters, for example `?statement_timeout=30000&idle_in_transaction_session_timeout=30000`. PgBouncer applies them to every Hatchet transaction and to no other client. Without the `track_extra_parameters` entry, PgBouncer rejects the connection.

On older PgBouncer versions, or if you can't change the PgBouncer config, set the timeouts on the role PgBouncer connects as, for each Hatchet database:

```sql
ALTER ROLE <hatchet_user> IN DATABASE <database> SET statement_timeout = '30s';
ALTER ROLE <hatchet_user> IN DATABASE <database> SET idle_in_transaction_session_timeout = '30s';
```

New server connections pick up these defaults; run `RECONNECT` on the PgBouncer admin console, or restart PgBouncer, to replace existing ones. Migrations turn both timeouts off on their own connections, so they aren't affected. Other sessions with that role, such as `psql` or `pg_dump`, get the defaults too; run `SET statement_timeout = 0` in those sessions for long operations.

## Example usage with `docker-compose`

```
version: "3.8"
services:
  postgres:
    image: postgres:15.6
    command: postgres -c 'max_connections=500' -c 'shared_preload_libraries=auto_explain' -c 'auto_explain.log_min_duration=1000' -c 'auto_explain.log_analyze=on' -c 'auto_explain.log_verbose=on' -c 'auto_explain.log_timing=on' -c 'auto_explain.log_buffers=on' -c 'auto_explain.log_wal=on' -c 'auto_explain.log_triggers=on' -c 'auto_explain.log_format=text'
    restart: always
    environment:
      - POSTGRES_USER=hatchet
      - POSTGRES_PASSWORD=hatchet
      - POSTGRES_DB=hatchet
    ports:
      - "5431:5432"
    volumes:
      - hatchet_postgres_data:/var/lib/postgresql/data
    shm_size: 4g
  pgbouncer:
    image: edoburu/pgbouncer:v1.26.0-p0
    restart: always
    environment:
      - DATABASE_URL=postgres://hatchet:hatchet@postgres:5432/hatchet
      - AUTH_TYPE=plain
    volumes:
      - ./pgbouncer.ini:/etc/pgbouncer/pgbouncer.ini:ro
    ports:
      - "6431:6432"
    depends_on:
      - postgres
```

With this `pgbouncer.ini` next to the compose file:

```ini
[databases]
hatchet = host=postgres port=5432 auth_user=hatchet

[pgbouncer]
listen_addr = 0.0.0.0
listen_port = 6432
auth_type = plain
auth_file = /etc/pgbouncer/userlist.txt
admin_users = postgres
pool_mode = transaction
max_client_conn = 1000
default_pool_size = 50
ignore_startup_parameters = extra_float_digits
track_extra_parameters = statement_timeout, idle_in_transaction_session_timeout
```

And point Hatchet at it:

```
DATABASE_URL='postgresql://hatchet:hatchet@127.0.0.1:5431/hatchet'
DATABASE_PGBOUNCER_URL='postgresql://hatchet:hatchet@127.0.0.1:6431/hatchet?statement_timeout=30000&idle_in_transaction_session_timeout=30000'
```
