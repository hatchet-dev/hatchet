## Running commands

`exec` runs a shell command in the workspace and returns its output once it finishes.

<UniversalTabs items={["Typescript"]}>

- The result has `stdout`, `stderr` and `exitCode`. A non-zero exit code is a result, not an error.
- `timeoutMs` stops the command after that long. A timed-out command returns exit code `124`.

## Restricting network access

`egress` on `create` sets the sandbox's outbound network policy. Without it the sandbox gets the provider's default, which is open internet on most providers. The policy replaces that default and is applied again whenever the sandbox is restored from a snapshot.

```typescript
const sandbox = await hatchet.sandbox.create({
  egress: { allow: ["*.github.com", "registry.npmjs.org", "10.0.0.0/8"] },
});
```

- `'allow-all'` and `'deny-all'` set the whole policy.
- `{ allow: [...] }` denies everything but its entries. `{ deny: [...] }` allows everything but its entries.
- An entry is a domain such as `example.com` or `*.example.com`, an IP address, or a CIDR. Ports and paths are not supported.
- Daytona, Modal and Freestyle only take allow lists and `'deny-all'`. Freestyle matches IPs and CIDRs only. Deny lists take IPs and CIDRs on every provider.
- A provider that cannot express the policy fails the create with its own message. See [Providers](/v1/sandboxes/providers) for each provider's limits.
- A self-hosted Brickie cluster ignores `egress` and `resources`. Set network policies and machine sizes in the cluster's Helm values instead.

## Working with files

`sandbox.files` reads and writes the workspace. Paths are relative to it.

<UniversalTabs items={["Typescript"]}>

- `read`, `write`, `list`, `exists`, `getInfo`, `makeDir`, `rename`, `copy` and `remove` are the file operations. A path outside the workspace throws a `FilesystemError` with code `invalid_path`.
- `read` and `write` carry up to 2 MiB per file. Larger files are not supported on Hatchet Cloud providers yet. A larger `read` fails with code `too_large` and a larger `write` with code `invalid`. One workaround is to fetch the file inside the sandbox and operate on it there.

## Forks

Start a new sandbox from any snapshot with `create({ from })`. A snapshot ID comes from the `snapshotId` on a call's result, or from `latestSnapshot` in `hatchet.sandbox.list()` once the sandbox was killed. Create two from the same snapshot and you have a fork, which is how you try two approaches from the same starting point.

## Finding and cleaning up

`hatchet.sandbox.list({ metadata })` returns the sandboxes whose tags include every pair you pass. `hatchet.sandbox.delete({ metadata })` deletes every match with all of its snapshots, and returns their IDs. Both filters are subset matches, so `{ conversation: "42" }` matches a sandbox tagged `{ conversation: "42", user: "ada" }`.

`kill()` stops the machine and keeps the snapshots, so `connect` still works and the provider stops billing you for a running machine. `delete()` removes the sandbox and its snapshots from the provider.

<Callout type="info">
  Idle sandboxes stop on their own after the provider's max idle time, 3600
  seconds by default. Stopped sandboxes still hold their snapshots at the
  provider until you delete them.
</Callout>
